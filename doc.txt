Abstract

ParseQRi is an enterprise-grade, AI-powered natural language to SQL platform designed to bridge the SQL skills gap in data-driven organisations. The system operates entirely on-premise using locally deployed language models (dolphin3:8b and deepseek-coder:6.7b) via Ollama, ensuring zero data transmission to external services. It employs a multi-agent orchestration architecture with six specialised agents coordinated by a Supervisor Agent, supporting dual data source workflows: direct MSSQL Server connectivity and CSV file analysis via a PostgreSQL-backed CSV Agent pipeline. A deterministic SQL Hardening layer using sqlglot AST validation prevents injection attacks, while intelligent caching with fuzzy query matching delivers sub-100ms response times. Built on React 18, FastAPI, and ChromaDB, the platform achieves 88%+ intent classification accuracy, 92% SQL generation success rate, and supports 100+ concurrent users, positioning it as a privacy-compliant alternative to cloud-dependent Text-to-SQL solutions.

Executive Summary

ParseQRi is an enterprise-grade, AI-powered natural language to SQL platform that enables business users and data analysts to interact with their databases using conversational queries. By leveraging a sophisticated multi-agent orchestration architecture, the system eliminates the need for SQL expertise while maintaining high accuracy, security, and performance standards.

In today's data-driven landscape, organisations face a critical challenge: the vast majority of business stakeholders who need data insights lack the technical SQL skills to access them directly. Traditional approaches such as hiring more data analysts, building custom dashboards, or training non-technical staff are costly, time-consuming, and often create bottlenecks. ParseQRi addresses this fundamental gap by transforming natural language questions into precise, optimised SQL queries through an intelligent multi-agent pipeline.

The platform's unique value lies in its on-premise AI architecture, which eliminates the data privacy concerns associated with cloud-based alternatives while delivering enterprise-grade performance. Unlike competitors that route sensitive business queries through third-party AI APIs, ParseQRi processes all natural language understanding locally, ensuring complete data sovereignty and regulatory compliance.

The system also supports dual data source workflows. Users can either connect to an existing Microsoft SQL Server database or upload CSV files for analysis. Both pathways are seamlessly integrated through a unified frontend interface.

This document provides a comprehensive technical overview designed for both technical leadership evaluating architectural decisions and sales engineering teams positioning the solution against competitive offerings.

Agent Specifications

Agent, Model, Context Window, Purpose
Intent Classification, dolphin3:8b, 2048 tokens, Classify query intent and extract semantic meaning
Schema Filtering, dolphin3:8b, 3072 tokens, Identify relevant tables and columns from schema
SQL Generation, deepseek-coder:6.7b, 4096 tokens, Generate syntactically correct SQL queries
SQL Validation, deepseek-coder:6.7b, 3072 tokens, Validate query correctness and optimise structure
SQL Hardening, sqlglot (code-based), N/A, Deterministic AST-based SQL security checks
Response Formatting, dolphin3:8b, 2048 tokens, Transform results into user-friendly responses

Model Strategy: The system uses only two distinct LLM models to prevent Ollama model thrashing and optimise VRAM utilisation. Domain-specific models (deepseek-coder) handle SQL tasks, while general-purpose models (dolphin3) manage orchestration and formatting. The SQL Hardening layer is entirely code-based, using sqlglot for deterministic validation without any LLM dependency.

Agent Deep Dive

Intent Classification Agent: This agent serves as the first line of understanding, analysing the user's natural language query to determine what type of database operation is being requested. It distinguishes between data retrieval queries, aggregation requests, comparison operations, and complex analytical questions. The confidence score it produces is critical. Queries with confidence below 70% trigger a clarification request rather than proceeding with potentially incorrect interpretations.

Schema Filtering Agent: Once intent is established, this agent examines the database schema stored in ChromaDB to identify which tables, columns, and relationships are relevant to the query. This filtering is essential for large databases with hundreds of tables, as it reduces the context window burden on the SQL generation agent and improves query accuracy by focusing on relevant schema elements only.

Schema Understanding Agent: This agent works alongside the Schema Filtering Agent. It connects directly to the MSSQL Server, extracts full schema metadata (tables, columns, data types, primary keys, foreign keys, and indexes), and stores it in ChromaDB as vector embeddings. This ensures the system has an up-to-date understanding of the database structure available for semantic search.

SQL Generation Agent: The core of the Text-to-SQL pipeline, this agent employs Chain-of-Thought (CoT) prompting to break down complex queries into logical steps before generating the final SQL. Using the deepseek-coder model specifically trained on code generation tasks, it produces syntactically correct, optimised SQL queries that respect the database schema constraints. It includes schema-qualified table names (e.g., dbo.TableName) for MSSQL compliance.

SQL Validation Agent: Before any query reaches the database, this agent performs a comprehensive validation pass. It checks for common SQL anti-patterns, verifies JOIN conditions, ensures proper aggregation with GROUP BY clauses, and confirms that all referenced tables and columns exist in the schema.

SQL Hardening (Code-based): Unlike the LLM-based agents, this is a deterministic code layer using sqlglot for AST (Abstract Syntax Tree) parsing. It provides an additional security layer by preventing SELECT *, validating table existence, verifying column references, checking GROUP BY compliance, and ensuring queries are safe for execution.

Response Formatting Agent: The final agent transforms raw query results into human-readable responses. It generates natural language summaries, suggests relevant visualisations (bar, line, pie, or table), and formats tabular data for optimal readability in the frontend interface.


1. Connect to SQL Database: The user provides the MSSQL Server name and database name. The system tests the connection, saves the configuration, and extracts metadata into ChromaDB. The user is then redirected to the SQL Dashboard.

CSV Agent Pipeline

In addition to the Text-to-SQL pipeline for connected databases, ParseQRi includes a CSV Agent that handles natural language queries over uploaded CSV files. This pipeline operates within the ParseQri_MCP module.

CSV Agent Workflow

1. File Upload: The user uploads a CSV file through the frontend. The backend saves the file and triggers processing via the CSV Agent service.
2. Data Ingestion: The CSV Agent parses the file, infers column types, and loads the data into a PostgreSQL database as a queryable table.
3. Natural Language Query: Users ask questions about their CSV data in natural language. The CSV Agent translates these into PostgreSQL-compatible SQL queries and executes them against the ingested data.
4. Result Formatting: Query results are formatted and returned with optional visualisation suggestions.

CSV Agent API Endpoints

Endpoint, Method, Purpose
/csv/query, POST, Process a natural language query against CSV data
/csv/execute_sql, POST, Execute a raw SQL query directly
/csv/upload, POST, Upload a CSV file for analysis
/csv/tables, GET, List available tables for the authenticated user
/csv/schema/{table_name}, GET, Get schema information for a specific table

The CSV Agent shares the same authentication layer (JWT) as the main application, ensuring consistent security across both data source types.

Database Management Module

ParseQRi provides a comprehensive database management module that handles connection lifecycle, metadata extraction, and schema storage.

Database Connection Workflow

1. Connection Configuration: Users provide the MSSQL Server name and database name. The system supports both Windows Authentication (Trusted Connection) and SQL Server Authentication.
2. Connection Testing: Before saving, the system tests the connection using the DatabaseConnectorFactory and MSSQLConnector classes. This validates that the server is reachable and the database is accessible.
3. Metadata Extraction: Once connected, the MetadataExtractionService extracts comprehensive schema metadata. This includes all tables, columns, data types, primary keys, foreign keys, and indexes.
4. ChromaDB Storage: Extracted metadata is stored as vector embeddings in ChromaDB using Ollama's all-MiniLM-L6-v2 embedding model. This enables semantic search during query processing.
5. Schema Caching: Schema metadata is also persisted as JSON files for fast retrieval and offline access.

SQL Security (Hardening Layer)

The system implements a multi-layered SQL security approach:

1. Syntax Parsing Validation: Every generated query is parsed via sqlglot to verify syntactic correctness.
2. Schema Validation: Tables and columns are verified against the actual database schema.
3. SELECT * Prevention: Enforces explicit column selection to prevent data over-exposure.
4. GROUP BY Compliance: Validates aggregation queries for correctness.
5. Injection Prevention: Parameterised query execution for all dynamic values.

Data Isolation

Mechanism, Description
User Database Segregation, Each user's uploaded data and database configs are isolated by user ID
Schema-Qualified Queries, All generated SQL includes explicit schema prefixes (e.g. dbo.TableName)
ChromaDB Collection Isolation, Vector embeddings are partitioned by server and database identifiers

On-Premise AI Processing

Unlike cloud-based Text-to-SQL solutions, ParseQRi processes all natural language queries locally via Ollama. This ensures:
- Zero data transmission to external AI services
- Complete regulatory compliance (GDPR, HIPAA, SOC 2)
- Intellectual property protection for sensitive business queries

Threat Mitigation Summary

Threat Vector, Mitigation Strategy, Implementation
SQL Injection, Multi-layer validation + parameterised queries, sqlglot AST parsing + prepared statements
Unauthorised Access, JWT with short expiry + refresh rotation, 15-min access tokens 7-day refresh tokens
Data Exfiltration, On-premise AI + user database isolation, No external API calls; per-user data contexts
Credential Theft, bcrypt hashing + no plaintext storage, Salt-per-password with automatic rotation
Session Hijacking, Token-based session with device binding, Token binding to client characteristics
Schema Information Leak, Schema-qualified queries + collection partitioning, ChromaDB isolation by server/database

Efficiency Features

Intelligent Caching System

ParseQRi implements a multi-tier caching strategy for optimal response times:

Cache Layer, Technology, Use Case, Latency Impact
Query Cache, Answer.json with fuzzy matching, Previously answered questions, ~50ms response
Schema Cache, ChromaDB + JSON file persistence, Database metadata, Eliminates schema re-extraction
Session Cache, In-memory token verification, User authentication state, Sub-millisecond verification

Fuzzy Matching Intelligence: The AnswerCacheService in cache_service.py employs SequenceMatcher-based similarity scoring with a configurable threshold (default: 85%). This enables cache hits on semantically similar queries even with minor phrasing variations. The cache supports both exact match (case-insensitive) and fuzzy match lookups.

Performance Optimisation Strategies

Optimisation, Technical Implementation, Result
Context Window Tuning, Per-agent context window sizes (2K-4K), Reduced inference latency; optimal memory use
Model Keep-Alive, Ollama keep_alive=10m configuration, Eliminates cold-start delays between queries
Async Processing, Python asyncio throughout the pipeline, Non-blocking I/O; concurrent request handling
Connection Pooling, SQLAlchemy connection pools, Reduced database connection overhead
Retry with Backoff, Configurable retry limits (Intent: 1 SQL: 3), Graceful handling of transient failures
Integration Service, TextToSQLIntegrationService caching, Reuses system instances per database connection

Confidence-Based Processing

The supervisor agent implements confidence thresholds to ensure response quality:
- Intent Classification Threshold: 70% minimum confidence required to proceed.
- SQL Generation Retries: Up to 3 attempts with progressive model adjustment.
- Automatic Clarification: Low-confidence responses trigger user clarification requests instead of generating potentially incorrect SQL.

Conclusion

ParseQRi represents a significant advancement in Text-to-SQL technology, combining the conversational accessibility of modern AI with the security, compliance, and performance requirements of enterprise deployments. The multi-agent architecture provides both accuracy and explainability, while on-premise AI processing ensures complete data sovereignty.

The platform supports dual data source workflows, allowing users to either connect to existing MSSQL Server databases or upload CSV files for immediate analysis. This flexibility makes ParseQRi suitable for a wide range of users, from database administrators working with production systems to business analysts exploring spreadsheet data.

The platform addresses a fundamental challenge in today's data-driven organisations: making data accessible to everyone who needs it, regardless of their technical expertise. By combining sophisticated AI orchestration with enterprise-grade security, ParseQRi enables organisations to unlock the full value of their data assets while maintaining complete control over sensitive information.

For organisations seeking to democratise data access without compromising security posture or incurring unpredictable cloud AI costs, ParseQRi offers a compelling, future-proof solution.
