# ParseQRi Updates & Migration Notes

**Date:** 2026-02-02
**Version:** 2.1.0

This document outlines the significant architectural changes, feature enhancements, and refactoring efforts undertaken to modernize the ParseQRi platform, specifically focusing on the CSV Analysis module.

## 1. Architectural Changes

### Module Isolation Strategy

A critical issue was identified where the `CSV_Agent` and the `Text_to_Sql` module (used by the main app) had conflicting module names and shared state in Python's `sys.modules`, leading to import errors when both were used.

- **Previous Implementation:** Standard import mechanisms caused collisions between `Text_to_Sql.config` and `CSV_Agent.TextToSQL_Agent.config`.
- **New Implementation:** Implemented a robust module isolation hack using `importlib` and `sys.modules` manipulation.
  - The `Text_to_Sql` module is now loaded dynamically as a separate namespace (`Text_to_Sql_Isolated`) when triggered via the `/api/text-to-sql` endpoint.
  - This ensures that the `CSV_Agent` can operate independently without its global configuration interfering with the main Text-to-SQL pipeline, and vice versa.

### Backend Endpoint Expansion

- **New Endpoint:** `/csv/execute_sql`
  - Enables direct execution of raw SQL queries against the user's data context.
  - Bypasses the LLM generation step, offering a deterministic path for power users.
- **Refactored Endpoint:** `/api/text-to-sql`
  - Updated to use the new isolated loading mechanism.
  - Improved error handling and response formatting.

## 2. Feature Enhancements

### CSV Analyst Dashboard (Frontend)

The `CsvDashboard` component has been completely re-engineered to provide a state-of-the-art conversational experience.

- **Conversational Interface:** Replaced the static sidebar layout with a dynamic Chat UI. Users can now see a history of their queries and the system's responses.
- **Inline Data & Schema:**
  - **Data Tables:** Query results are rendered directly in the chat stream as interactive tables.
  - **Schema Views:** Users can inspect table schemas within the chat context without leaving the conversation.
- **SQL Transparency & Control:**
  - **Code Block Display:** The SQL query generated by the AI is now visible in the chat bubble.
  - **Integrated SQL Editor:** Users can click to edit the generated SQL and re-execute it immediately using the new **SQL Editor** embedded in the chat message.
  - **"Run Query" Action:** A dedicated button allows for rapid iteration and verification of SQL logic.

### Legacy Features Removed

- **Static Assistant Sidebar:** The separate "AI Assistant" sidebar in the CSV view was redundant and has been removed in favor of the main chat interface.

## 3. Implementation Details

### Backend Refactoring (`integration_service.py`)

- Added `execute_sql` method to `CsvAgentService`.
- This method manually constructs a `QueryContext` to allow the `query_execution` agent to run raw SQL without requiring a full LLM pipeline pass.

### Frontend Service Layer (`csvAgent.ts`)

- Added `executeSql(sqlQuery)` method to abstract the API call.
- Updated `processQuery` handling to correctly propagate the `sql_query` field to the UI.

## 4. Migration Guide

If you are upgrading from a previous version:

1.  **Frontend:** Run `npm install` to ensure `react-icons` and other new dependencies are up to date (though no major package changes were made).
2.  **Backend:** No database migration is required. The changes are primarily logic-based.
3.  **Restart Services:** You must restart the FastAPI server (`uvicorn`) to pick up the new endpoint definitions and module loading logic.

## 5. Known Limitations

- **SQL Dialect:** The system currently targets the dialect configured in the backend (defaulting to SQLite/PostgreSQL logic depending on the `db_url`). Ensure your raw SQL queries match the underlying database engine syntax.
- **Security:** Manual SQL execution is powerful. Ensure that the backend `postgres_handler` (or equivalent) continues to enforce read-only permissions if deployed in a restricted environment.
