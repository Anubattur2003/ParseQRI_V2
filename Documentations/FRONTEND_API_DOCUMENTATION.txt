PARSEQRI FRONTEND API DOCUMENTATION
=================================

Base URL: http://localhost:8000
Authentication: Bearer Token (JWT)

This document outlines the API services used by the ParseQri frontend application, organized by the service modules in `frontend/src/services/`.

================================================================================
1. MAIN API SERVICE (src/services/api.ts)
================================================================================

This file contains the core `apiClient` instance with strict interceptors for JWT token handling and automatic refreshing.

1.1 Authentication (authService)
--------------------------------
- register(username, email, password): POST /auth/register
- login(username_or_email, password): POST /auth/login
- getCurrentUser(): GET /auth/me
- checkAuth(): POST /auth/token/verify/
- logout(): Clears local storage

1.2 Database Configuration (dbService)
--------------------------------------
- getConfigs(): GET /db/config
- createConfig(config): POST /db/config
- createDefaultConfig(): POST /db/default-config

1.3 Text-to-SQL & Database (textToSqlService)
---------------------------------------------
- getDatabases(): GET /api/databases
- processQuery(query, visualization, databaseId): POST /api/text-to-sql
  * Used for querying connected MSSQL/MySQL databases via the Text-to-SQL LangGraph agent.

1.4 Visualization (visualizerService)
-------------------------------------
- generateVisualization(queryId, chartType): POST /visualizer/generate/
- getRecommendedChartType(data): POST /visualizer/recommend-chart/
- exportData(queryId, format): POST /visualizer/export/

1.5 Datasets (datasetService)
-----------------------------
- getDatasets(): GET /datasets/
- uploadDataset(formData): POST /datasets/upload/
- uploadCsv(file, dbId): POST /data/upload/{dbId} (Backend proxy/temp)

================================================================================
2. CSV AGENT SERVICE (src/services/csvAgent.ts)
================================================================================

This service interacts with the `ParseQri_MCP/CSV_Agent` endpoints via the `/csv` prefix.

2.1 Querying
------------
- processQuery(query, tableName, visualization, databaseId): POST /csv/query
- executeSql(sqlQuery): POST /csv/execute_sql

2.2 Management
--------------
- uploadCsv(file, dbId): POST /csv/upload
- listTables(): GET /csv/tables
- getTableSchema(tableName): GET /csv/schema/{tableName}

================================================================================
3. AUTHENTICATION FLOW
================================================================================

3.1 Request Interceptor
-----------------------
Automatically adds `Authorization: Bearer <token>` to all requests if a token exists in localStorage.

3.2 Response Interceptor
------------------------
Handles 401 Unauthorized responses:
1. Detects 401 status.
2. Checks for `refresh_token` in localStorage.
3. Calls `POST /auth/token/refresh/`.
4. If successful:
   - Updates `localStorage` with new access token.
   - Retries the original failed request with the new token.
5. If failed:
   - Clears tokens.
   - Redirects to `/login`.

================================================================================
4. ERROR HANDLING
================================================================================

- Standard HTTP Status Codes (200, 400, 401, 403, 404, 500).
- Backend returns detailed error messages in `error.response.data.detail`.
- Frontend services throw Error objects containing these details for UI consumption.

================================================================================

This document outlines all API endpoints used by the ParseQri frontend application, organized by functionality.

================================================================================
1. AUTHENTICATION SERVICES
================================================================================

1.1 User Registration
---------------------
Endpoint: POST /auth/register
Purpose: Register a new user account
Request Body:
{
  "username": "string",
  "email": "string", 
  "password": "string"
}
Response:
{
  "id": "number",
  "username": "string",
  "email": "string"
}
Frontend Function: authService.register(username, email, password)

1.2 User Login
--------------
Endpoint: POST /auth/login
Purpose: Authenticate user and get access tokens
Request Body:
{
  "username_or_email": "string",
  "password": "string"
}
Response:
{
  "access": "string (JWT token)",
  "refresh": "string (refresh token)",
  "token_type": "bearer"
}
Frontend Function: authService.login(username_or_email, password)

1.3 Token Refresh
-----------------
Endpoint: POST /auth/token/refresh/
Purpose: Refresh expired access token using refresh token
Request Body:
{
  "refresh": "string (refresh token)"
}
Response:
{
  "access": "string (new JWT token)",
  "token_type": "bearer"
}
Frontend Function: Automatically handled by axios interceptor

1.4 Token Verification
----------------------
Endpoint: POST /auth/token/verify/
Purpose: Verify if a token is valid
Request Body:
{
  "token": "string (JWT token)"
}
Response:
{
  "valid": true
}
Frontend Function: authService.checkAuth()

1.5 Get Current User
--------------------
Endpoint: GET /auth/me
Purpose: Get current authenticated user information
Headers: Authorization: Bearer <token>
Response:
{
  "id": "number",
  "username": "string", 
  "email": "string"
}
Frontend Function: authService.getCurrentUser()

1.6 Logout
----------
Purpose: Clear local storage and redirect to landing page
Frontend Function: authService.logout()
Note: This is a client-side operation that clears tokens from localStorage

Headers: Authorization: Bearer <token>

{

2.6 Search Metadata
-------------------

Purpose: Search metadata using query string
Headers: Authorization: Bearer <token>

6. AUTHENTICATION INTERCEPTORS
================================================================================

6.1 Request Interceptor
-----------------------
Purpose: Automatically add Authorization header to all requests
Implementation: Adds "Bearer <token>" header from localStorage

6.2 Response Interceptor
------------------------
Purpose: Handle 401 Unauthorized responses and token refresh
Implementation: 
- Detects 401 responses
- Attempts token refresh using refresh token
- Retries original request with new token
- Redirects to login if refresh fails

================================================================================
7. ERROR HANDLING
================================================================================

7.1 HTTP Error Responses
-------------------------
- 400 Bad Request: Invalid request data
- 401 Unauthorized: Invalid or expired token
- 403 Forbidden: Insufficient permissions
- 404 Not Found: Resource not found
- 422 Unprocessable Entity: Validation errors
- 500 Internal Server Error: Server-side errors

7.2 Frontend Error Handling
----------------------------
- All API functions use try-catch blocks
- HTTP errors are extracted from error.response.data.detail
- Tokens are automatically refreshed on 401 errors
- Users are redirected to login on authentication failures

8. CONFIGURATION
================================================================================

8.1 Base Configuration
-----------------------
- API Base URL: http://localhost:8000
- Default Content-Type: application/json
- Authentication: JWT Bearer tokens
- Token Storage: localStorage

7.2 Token Management
--------------------
- Access Token Key: 'token'
- Refresh Token Key: 'refresh_token'
- Username Key: 'username'
